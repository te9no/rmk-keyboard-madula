# v0.1.0-rc.8 — Madulaバッテリー残量表示の修正

Madulaで電圧から推定した残量がBluetoothに反映されず、0%表示になる問題を修正しました。

- NiMH 1本用の推定残量をRMKの状態キャッシュとBluetooth通知へ反映。
- 起動後の初回計測を早め、読み取り要求には最新の残量を返します。
- 未計測・測定異常を0%として返さず、残量不明として扱います。
- 同じ残量の重複通知と、キューに残った古い残量の通知を抑制します。
- 充電状態は不明として扱います。電圧からの推定値であり、精密な残量計ではありません。

## ファイルの選択

| モジュール | Vial版 | Rynk版（gui.rmk.rs） |
| --- | --- | --- |
| LPPS | madula-lpps.uf2 | madula-lpps-rynk.uf2 |
| PMW3610 / TB | madula-tb.uf2 | madula-tb-rynk.uf2 |
| IQS9151 | madula-iqs.uf2 | madula-iqs-rynk.uf2 |

既存のRMK版Cornix左右はそのまま使用できます。CornixTPには専用のcornix-tp.uf2を使ってください。
rc.7のDial・BLE入力・IQS改善、rc.6のRynk v0.2対応を維持しています。

## 実機確認と制限

修正コードのTB Vial版を実機へ書き込み、再起動とPMW3610の認識・継続動作ログを確認しました。
その際の電池電圧はほぼ0Vで、残量不明として扱われています。
有効な電池電圧での残量表示と、接続先の0%通知が停止することは未確認です。

同じ実機でBluetoothのペアリング鍵が見つからず再接続に失敗するログを確認しました。
同様の症状がある場合は、接続先の「Madula RMK」を削除して再ペアリングしてください。
この変更では保存領域・スキーマIDを変更していませんが、既存ペアリングの維持は保証できません。

## 検証

バッテリー換算・状態反映・重複抑制・無効値の回帰テスト4件と設定テスト19件が成功。
配布ビルドの検証方法は同梱のBUILD-PROVENANCE.mdを参照してください。

UF2は0x1000から配置するRMK SDCアプリで、旧SoftDeviceを上書きします。ZMKアプリの更新ファイルではありません。
JSONにソースコミットとハッシュ、SHA256SUMSに配布物のハッシュを収録します。実機バックアップは含みません。
